# 安全边界

## 所有权与输入
- 默认 shared，普通玩家拥有共享仓和世界接口权限；个人仓仅本人 UUID 可访问。权限插件仍可显式拒绝共享仓/接口，管理与恢复权限仍默认 OP。接口以绑定时身份固定，玩家切换仓库不改变已有端口，输入和输出分别按本人 UUID 限额 5 个，跨世界/仓库合并计数。
- 物品元数据、数据组件、附魔、容器内容全部参与物品键。新入库仅接受普通可堆叠无 ItemMeta 物品，拒绝装备/工具/潜影盒/玩家头颅；配置禁用材料作为额外限制。升级前的特殊存量仍可从普通菜单/命令取出。客户端提交的数量和图标不用于入账。
- 菜单取消原版点击，按服务器最新记录处理；拒绝拖拽、双击聚集、数字键交换、创造复制与丢弃。普通仓库要求空光标；打印窗口支持服务端真实光标的左/右键存取、内部槽位搬运及 Shift，禁止客户端预测物品成为记账依据。
- 云潜影盒不是物品副本容器；禁止放置、转存、丢弃、死亡掉落、制作与原版开盒，携带者必须与 PDC UUID 相符。目录只展示无元数据的普通可放置方块。按需 payload 只接受有限材料名，不接收玩家 UUID、仓库标识、数量或物品数据；服务端使用消息实际发送者并验证绑定权限。请求只改变索引，真实取料始终再检查余额。光标也是外部库存，转移快照的最后一项记录光标；意外关闭交由 Paper 将已扣账的真实光标物品归还，不能重放发货。

## 崩溃与恢复
SQLite 与 Minecraft playerdata/chunk 文件没有跨存储原子提交，不能承诺任意断电下绝对不丢物品。事务 journal 保障云仓不出现负数/重复扣账；数据库错误或 dirty 启动时暂停所有交易，绝不重放物品。

管理员须备份数据库、玩家和世界存档，核对 journal 外部快照和实际物品位置。`recover <id> before|after` 选择外部库存实际处于哪个状态：before 撤销云仓增减，after 保留云仓增减；两者都不自动给玩家物品。全部 PENDING 处理完成后，`recover unlock` 表示已审计非正常停机以来的 DONE 操作，才能解除 dirty 冻结。错误选择可能造成重复或丢失，不能用自动脚本盲目恢复。

受控关闭先关闭所有菜单与交易，保存玩家/世界后只写 shutdown_ready 候选，dirty 保留。0.2.2 可直接由面板启动：关闭钩子在只读校验 Paper 1.21.1 完整关闭与正常退出标志后，写入同 session 的原子凭据，数据库不在 onDisable/钩子中解冻；下次启动确认旧 JVM 已退出、候选匹配且无 PENDING 才接受。旧 supervisor 的退出码 0 finalizer 仍可使用。进程尚活、过期凭据、kill-after-onDisable、abnormalExit、热卸载及 PENDING 均保持冻结。

不依赖日志文字或单独 pending=0 来判断已保存。遗留冻结不会自动迁移为正常；需审计后一次人工确认。凭据与数据库/世界文件一样必须受服务器文件系统权限保护，不能手工伪造或混用备份。禁止 /reload、热卸载或强杀；底层设备缓存仍不具有数据库/世界联合 fsync，生产仍需联合备份。

初始化失败时插件保留云潜影盒事件保护并拒绝命令，防止目录进入原版取物路径。移除、热卸载本插件，或携带目录物品进入没有该插件的世界不受支持；上线前必须持续启用保护。

0.2.3 针对 AxShulkers 1.24.0 安装事件隔离。其开盒监听器不检查已取消事件，单纯 event.setCancelled 不足；CloudStorage 在 Ax 的 PluginEnableEvent 完成后，用委托包装其现有 Bukkit 注册。云目录物品与 CloudStorage 窗口跳过 Ax 回调，普通事件调用原 RegisteredListener，保留原 priority、ignoreCancelled 和插件归属（Ax 禁用时仍由 Bukkit 自动注销）。不修改 Ax 文件、缓存或数据库，也不把目录副本交给其持久化层。已知版本/监听器布局不匹配、出现未包装注册时，云盒继续关闭；不支持热加载与第三方动态替换监听器。其他开盒插件仍需独立适配，不可推断为普适兼容。

不信任其他插件：本插件保留自己的窗口/云潜影盒事件并优先取消；与任意可改库存的第三方插件不存在普适兼容保证。不要同时启用其他插件对云潜影盒的打开。真实 Fabric 打印客户端的端到端验证须单独记录。
