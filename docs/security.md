# 安全边界

## 所有权与输入
- 默认每名玩家只能访问自己的 UUID；共享仓需要独立权限。接口以绑定时身份固定，玩家切换仓库不改变已有端口。
- 物品元数据、数据组件、附魔、容器内容全部参与物品键。新入库仅接受普通可堆叠无 ItemMeta 物品，拒绝装备/工具/潜影盒/玩家头颅；配置禁用材料作为额外限制。升级前的特殊存量仍可从普通菜单/命令取出。客户端提交的数量和图标不用于入账。
- 菜单取消原版点击，按服务器最新记录处理；拒绝拖拽、双击聚集、数字键交换、创造复制与丢弃。普通仓库要求空光标；打印窗口支持服务端真实光标的左/右键存取、内部槽位搬运及 Shift，禁止客户端预测物品成为记账依据。
- 云潜影盒不是物品副本容器；禁止放置、转存、丢弃、死亡掉落、制作与原版开盒，携带者必须与 PDC UUID 相符。目录只展示无元数据的普通可放置方块。按需 payload 只接受有限材料名，不接收玩家 UUID、仓库标识、数量或物品数据；服务端使用消息实际发送者并验证绑定权限。请求只改变索引，真实取料始终再检查余额。光标也是外部库存，转移快照的最后一项记录光标；意外关闭交由 Paper 将已扣账的真实光标物品归还，不能重放发货。

## 崩溃与恢复
SQLite 与 Minecraft playerdata/chunk 文件没有跨存储原子提交，不能承诺任意断电下绝对不丢物品。事务 journal 保障云仓不出现负数/重复扣账；数据库错误或 dirty 启动时暂停所有交易，绝不重放物品。

管理员须备份数据库、玩家和世界存档，核对 journal 外部快照和实际物品位置。`recover <id> before|after` 选择外部库存实际处于哪个状态：before 撤销云仓增减，after 保留云仓增减；两者都不自动给玩家物品。全部 PENDING 处理完成后，`recover unlock` 表示已审计非正常停机以来的 DONE 操作，才能解除 dirty 冻结。错误选择可能造成重复或丢失，不能用自动脚本盲目恢复。

受控关闭先关闭所有菜单与交易，保存玩家/世界后只写 shutdown_ready 候选，dirty 保留。Paper 世界 I/O 完成且实际 JVM 正常退出 0 后，启动脚本的 checkpoint.py 才能清除 active。必须使用提供的启动脚本；直接 java 启动或其他托管方式应在进程退出后接入同一 finalizer，否则下一次启动会保守冻结。禁止 /reload、插件热卸载或强制杀进程。底层存储设备缓存仍不属于数据库/世界联合 fsync，生产仍需联合备份。

初始化失败时插件保留云潜影盒事件保护并拒绝命令，防止目录进入原版取物路径。移除、热卸载本插件，或携带目录物品进入没有该插件的世界不受支持；上线前必须持续启用保护。检测到 AxShulkers 时不再发放/打开云潜影盒并清空在线玩家目录，避免两个开盒器竞争。

不信任其他插件：本插件保留自己的窗口/云潜影盒事件并优先取消；与任意可改库存的第三方插件不存在普适兼容保证。不要同时启用其他插件对云潜影盒的打开。真实 Fabric 打印客户端的端到端验证须单独记录。
